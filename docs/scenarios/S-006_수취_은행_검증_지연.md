# S-006 — 수취 은행 검증 지연

상태: 확정

## 목적

수취 은행의 장애로 검증 결과를 확인하지 못할 때 중앙 거래가 거절로 추측되지 않고 대기하는지 확인한다.

## 사전 조건

- 고객 A의 은행 A 계좌 `A-001` 잔액은 100,000원이다.
- 은행 B에 수취 계좌 `B-001`이 존재하고 잔액은 100,000원이다.
- 송금액은 10,000원이고 외부 거래 ID는 `E-104`다.
- 중앙 결제잔액은 은행 A와 은행 B가 각각 1,000,000원이다.

## 발생한 사건

1. 은행 A가 `A-001`에서 10,000원을 출금하고 출금 기록과 `송금중` 거래를 생성한다.
2. 중앙 결제 시스템이 `E-104`를 `수취검증대기`로 생성한다.
3. 은행 B의 프로세스 또는 통신 장애로 검증 대기 거래를 처리하지 못한다.

## 사건 흐름 다이어그램

```mermaid
sequenceDiagram
    autonumber
    actor 고객
    participant A as 은행 A
    participant C as 중앙 결제
    participant B as 은행 B

    고객->>A: 10,000원 송금 요청
    A->>A: 출금 및 출금 기록
    Note over A: 송금중
    A->>C: E-104 결제 요청
    Note over C: 수취검증대기
    Note over B: 프로세스 또는 통신 장애
    B-xC: 검증 대기 거래 처리 불가
    Note over C: 수취검증대기 유지
    Note over A: 송금중 유지
```

## 장애 직후 확인되는 사실

### 송금 은행

- `A-001` 잔액은 90,000원이고 출금 기록은 한 건이다.
- 로컬 송금 상태는 `송금중`이며 보상 기록은 없다.

### 중앙 결제 시스템

- `E-104` 상태는 `수취검증대기`다.
- 두 은행 결제잔액은 각각 1,000,000원으로 변하지 않는다.

### 수취 은행

- `B-001` 잔액은 100,000원이며 입금 기록은 없다.
- 수취 가능 또는 불가 결과가 아직 중앙에 전달되지 않았다.

## 최종 기대 결과

- 장애가 계속되는 동안 `E-104`는 `수취검증대기`, 은행 A의 송금은 `송금중`을 유지한다.
- 은행 B가 복구한 뒤 같은 대기 거래를 조회하여 계좌 존재를 확인하면 중앙 결제와 양쪽 은행의 로컬 반영을 계속할 수 있다.

## 금지되는 결과

- 응답이 없다는 이유만으로 `결제거절`이나 송금 `실패`를 확정해서는 안 된다.
- 결과 불명 상태에서 은행 A가 출금을 보상하거나 은행 B가 입금해서는 안 된다.

## 적용되는 불변식

- 수취 은행의 수취 가능 확인 없이 중앙 결제를 완료해서는 안 된다.
- 확인할 수 없는 결과를 추측하여 실패 처리하거나 보상해서는 안 된다.
