# 1주차 거래 시나리오

## 목적

1주차에 합의한 기능 요구사항, 상태 전이와 불변식을 구체적인 숫자와 사건 순서로 표현한다. 각 시나리오는 이후 구현과 테스트에서 기대 결과를 판단하는 기준으로 사용한다.

## 작성 범위

- 1주차에 합의한 도메인 계약만 작성한다.
- 구체적인 재시도 횟수, polling 주기, 동시성 제어 방식과 부하 조건은 해당 주차에 별도로 추가한다.
- 하나의 시나리오에서는 하나의 정상 흐름, 거절 또는 장애 지점만 다룬다.
- 송금 은행, 중앙 결제 시스템과 수취 은행의 사실을 분리한다.
- 장애 직후 허용되는 중간 상태와 최종적으로 수렴해야 하는 상태를 구분한다.
- 합의되지 않은 복구 방식은 기대 결과로 확정하지 않는다.
- 각 문서의 Mermaid 다이어그램은 `발생한 사건`을 시각화한 보조 자료이며, 본문에 없는 결정을 추가하지 않는다.
- `A-001`, `B-001`, `E-100` 같은 값은 시나리오를 읽기 위한 예시 표기다. 실제 `account_number`와 `transfer_key`는 데이터 모델에서 합의한 UUID를 사용한다.

## 별도 시나리오로 만들지 않은 내용

- 같은 은행 계좌 사이의 송금: MVP 제외 범위다.
- 은행 결제잔액 부족과 이후 유동성 회복: 부족 시 결제거절이라는 불변식만 유지하고, 예외적인 경우이므로 이번 핵심 시나리오에서는 다루지 않기로 합의했다.
- 일일 대사: 유지 여부가 미정이므로 시나리오에 포함하지 않는다.
- 보상과 완료 결제의 동시 존재: 정상 복구 흐름이 아니라 불변식 위반으로 각 관련 시나리오의 금지 결과에 둔다.

## 상태 표시

- `초안`: 합의한 내용으로 작성했지만 사용자 검토가 필요하다.
- `확정`: 사용자가 조건과 기대 결과를 승인했다.
