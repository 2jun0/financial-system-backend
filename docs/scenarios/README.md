# 시나리오 분류

시나리오 번호는 주요 책임과 복구 주체를 기준으로 구분한다. 장애가 발생한 물리적 위치보다 미확정 기록을 보유하고 다음 처리를 수행하는 시스템을 우선한다.

| 번호 | 분류 | 주요 내용 |
|---|---|---|
| `S-0xx` | 공통 기준 | 정상 흐름과 계좌 생성 |
| `S-1xx` | 송금 은행 | 요청 검증, 송금 상태, 확인 조회와 보상 |
| `S-2xx` | 중앙 결제 | 결제 접수, 수취 검증, 만료와 결제잔액 |
| `S-3xx` | 수취 은행 | 수취 기록, 결제 결과 반영과 확인 조회 |

각 분류의 시나리오는 해당 책임 주체가 관찰하고 변경하는 범위만 상세히 표현한다.

- `S-1xx`는 송금 은행과 중앙 결제 사이의 계약만 표현한다. 중앙 결제 내부 처리와 수취 은행의 처리는 숨긴다.
- `S-2xx`는 중앙 결제의 상태 변경과 복구를 표현한다. 송금·수취 은행은 중앙 결제와 상호작용하는 외부 참여자로만 표현한다.
- `S-3xx`는 수취 은행과 중앙 결제 사이의 계약만 표현한다. 송금 은행의 내부 처리는 숨긴다.
- 전체 시스템의 정상적인 협력 흐름은 `S-0xx`에서 표현한다.
- 로컬 DB 트랜잭션 커밋 전 장애처럼 롤백 후 같은 복구 과정을 반복하는 경우는 각 처리 지점마다 별도 시나리오로 만들지 않는다. 장애로 인해 새로운 업무 상태나 별도의 복구 판단이 생기는 경우에만 시나리오로 기록한다.

각 분류 안의 번호는 현재 존재하는 시나리오를 기준으로 연속되게 유지한다. 시나리오를 추가·삭제하거나 분류를 개편하면 파일명, 문서 제목과 문서 안의 참조 번호를 함께 다시 정리한다. 이 디렉터리는 과거 번호의 이력이 아니라 현재 설계를 보여준다.

각 분류 안에서는 다음 순서로 배치한다.

1. 정상 처리
2. 업무 규칙에 따른 거절
3. 요청·응답 유실과 복구

예시 송금 키는 원칙적으로 시나리오 번호와 같은 숫자를 사용한다. 다른 책임 구간에서 같은 거래를 이어서 다루는 시나리오는 최초 거래의 송금 키를 그대로 사용하여 두 시나리오의 연결을 드러낸다.
