# Financial System Backend

금융 거래에서 발생하는 데이터 정합성, 동시성, 트랜잭션, 멱등성, 장애 복구 문제를 직접 재현하고 해결하는 백엔드 프로젝트입니다.

특정 기술을 먼저 정해 적용하기보다 문제를 발견하고, 설계하고, 실패를 검증한 뒤 개선하는 과정을 중요하게 다룹니다.

## 만든 이유

금융 시스템은 데이터 정합성, 동시성 제어, 트랜잭션 관리처럼 백엔드에서 중요하게 다뤄지는 여러 문제가 복합적으로 나타나는 도메인입니다. 특히 돈을 다루기 때문에 작은 오류도 실제 손실이나 신뢰 훼손으로 이어질 수 있어 높은 수준의 정확성과 신뢰성이 요구됩니다.

이 프로젝트를 만든 이유는 이런 환경에서 발생할 수 있는 문제를 직접 상정하고 설계·구현·검증하면서 백엔드 시스템 설계 역량을 기르기 위해서입니다. 정상적인 기능 구현에 그치지 않고 부분 실패, 동시 요청, 중복 처리, 응답 유실, 외부 시스템 장애처럼 시스템을 깨뜨릴 수 있는 조건을 실제로 재현합니다.

또한 특정 기술을 사용하기 위해 문제를 끼워 맞추지 않습니다. 먼저 지켜야 할 규칙과 실패 조건을 정의하고, 여러 해결 방법의 정합성·복잡도·성능 trade-off를 비교한 뒤 선택 근거와 측정 결과를 기록합니다.

## 진행 원칙

> 문제 발견 → 직접 설계 → 구현 → 실패 및 검증 → 개선

- AI가 설계를 대신하게 하지 않습니다.
- AI는 작성한 설계의 반례 탐색, 기술 검토, 대안 비교를 위한 조언 도구로 활용합니다.
- ERD와 API를 먼저 만들기보다 시스템이 반드시 지켜야 할 불변식을 먼저 정의합니다.
- 최종 결과뿐 아니라 실패한 설계, 비교한 대안, 선택 근거와 측정 결과를 기록합니다.

## 구현 기술

- 은행 시스템과 모의 중앙 결제 시스템은 Kotlin, Spring Boot와 Java 25로 구현합니다.
- 각 시스템은 독립된 MySQL 데이터베이스를 사용하며 Flyway로 스키마를 관리합니다.
- 로컬 개발에 필요한 데이터베이스는 Docker Compose로 실행합니다.

## E2E 테스트

Java 25와 실행 중인 Docker가 필요합니다.

```bash
cd e2e
./gradlew test
```

은행 A·중앙 결제·은행 B와 각각의 MySQL을 자동 실행합니다.
각 테스트 전에 테스트 DB 데이터를 비우고, 테스트에 필요한 시드를 넣습니다.
테스트가 끝나면 컨테이너와 테스트 볼륨을 정리합니다.

개발 DB와 별도의 Compose 프로젝트를 사용하지만, 고정 포트(8081~8083, 3307~3309)를 공유합니다.
같은 포트를 사용하는 개발용 앱·DB가 실행 중이라면 먼저 종료해야 합니다.

## 8주 계획

### 1주차 — 도메인/불변식 설계

금융 거래의 규칙, 상태, 실패 조건을 직접 정의합니다. ERD와 API보다 먼저 “절대 깨지면 안 되는 조건”을 명시합니다.

### 2주차 — 최소 거래 시스템 구현

고객이 직접 시작하는 은행 간 송금의 최소 정상 흐름을 구현합니다. 송금 은행의 출금, 중앙 결제, 수취 은행의 입금과 거래 내역 조회를 우선 단순하게 만들어 이후 깨뜨리고 개선할 기반을 만듭니다.

### 3주차 — 트랜잭션과 정합성

부분 실패를 실제로 재현합니다. 트랜잭션 경계를 여러 방식으로 고민하고 선택 이유까지 기록합니다.

### 4주차 — 동시성 제어 실험

Race condition을 재현하고, 두 개 이상의 대안을 직접 구현해 비교합니다. 정합성뿐 아니라 성능도 측정합니다.

### 5주차 — 멱등성과 재시도

중복 요청, timeout, 응답 유실을 재현합니다. “처리는 됐지만 클라이언트는 실패로 인식하는 상황”까지 다룹니다.

### 6주차 — 장애 복구와 외부 시스템

외부 I/O 실패와 DB commit 전후 장애를 다룹니다. 재처리 전략과 transaction boundary를 다시 설계합니다.

### 7주차 — 공격적 검증

동시 요청, 장애, 중복, 부하 테스트를 수행합니다. 정의한 불변식이 깨지는 조건을 계속 찾고 성능 trade-off까지 확인합니다.

### 8주차 — 리팩토링 + 설계 기록

“무엇을 구현했는가”보다 아래 흐름을 보여주는 사례 3~5개를 정리합니다.

> 문제 → 최초 설계 → 실패 → 대안 → 선택 → 측정 결과
